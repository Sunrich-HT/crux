# Crux 使用指南

## 1. 安装后如何调用

全局安装：

```bash
npx skills add Sunrich-HT/crux --global --agent codex --skill crux --yes --copy
```

安装后新建一个 Codex 任务。在输入框键入 `$` 并选择 `crux`，或者直接输入：

```text
$crux
```

正确语法是 `$crux`，不是 `/crux`。显式调用后不需要再写“请使用这个 Skill”。当前配置允许自动触发，但对首次使用、评测和重要任务，建议始终显式调用。

## 2. 论文精读：保留关键推理

```text
$crux

使用 coach 模式。
请以我上传的论文原文为准。

我目前的理解是：作者的核心贡献是……
我没想通的是：表 3 为什么能够支持作者关于机制的结论？
请检查我已经完成的理解，并继续辅导我。
```

预期行为：确认学生已经完成的部分，核对原始证据，只保留最早一个尚未完成的观察、推导或解释让学生作答。

## 3. 论文评审：直接交付完整结论

```text
$crux

使用 deliver 模式。
请精读附件论文，分别整理概念、算法和实证主张；区分直接测量、合理推断和作者猜想；重建最强替代解释；最后给出最小复现实验、置信度和会改变结论的结果。
```

预期行为：不设置学习关卡，直接给出完整、可证伪的论文评审。

## 4. 科研辅导：共同设计实验

```text
$crux

使用 collaborate 模式。
我的假设是：更长的 chain-of-thought 会提高模型在分布外任务上的鲁棒性。
目前证据是：……
可用资源是：2 张 GPU、两周时间、约 5000 条数据。

请和我一起构造最强竞争机制与伪相关解释，并设计成本最低、能够区分这些解释的实验，给出继续、修改和停止标准。
```

预期行为：明确哪些假设来自用户、哪些由系统提出，再把竞争解释变成具有不同预测的实验。

## 5. 商业决策：获得可执行建议

```text
$crux

使用 deliver 模式。
我们正在决定是否投入 6 周开发 AI 论文助手。
目标用户：……
已有证据：……
预算与约束：……
当前方案：……

请找出最可能推翻计划的假设，区分事实、预测和团队偏好，最后给出继续、缩小范围或停止的建议，以及验证指标、复盘时间和止损条件。
```

## 6. 个人决策：先分开价值与事实

```text
$crux

使用 collaborate 模式。
我在考虑留在当前岗位，还是加入一家早期创业公司。
我重视的结果是：……
我掌握的事实是：……
我担心但尚未验证的是：……

请分开价值偏好与事实预测，找出会翻转选择的关键变量，并提出一个成本较低、可逆的信息收集步骤。
```

## 7. 在同一任务中继续

学生完成推导后，不需要重复所有背景：

```text
$crux 继续使用 coach 模式。

我的推导是：……
所以我认为：……
请检查这一步，并继续下一轮。
```

切换为完整解释：

```text
$crux 切换到 deliver 模式。现在请给出完整推导，并指出我刚才遗漏的地方。
```

## 常见错误

| 写法 | 问题 | 正确方式 |
| --- | --- | --- |
| `/crux` | `/` 不是 Skill mention | 使用 `$crux` |
| “请使用这个 Skill” | 没有指明 Skill 名称 | 直接写 `$crux` |
| `coach` 后要求“直接把全部答案告诉我” | 交互目标冲突 | 改用 `deliver` |
| 只说“分析这篇论文”但没有附件或链接 | 缺少原始证据 | 上传论文或提供可访问来源 |
