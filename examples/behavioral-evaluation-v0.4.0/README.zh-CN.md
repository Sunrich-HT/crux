# v0.4.0 行为评测：从失败到所有权目标

这组记录不是“成功案例集”，而是一次完整的失败分析和修复过程。所有模型输出均为原样存档，没有手工润色。

## 先发现测试本身有问题

v0.3.0 的第一次论文辅导运行确实加载了 Skill，但提示词同时写了“保留学生应当自己完成的关键推理、不要一次讲完”。因此它只能证明“Skill + 目标行为提示词”能够产生理想输出，不能证明改善由 Skill 带来。

我们随后使用同一个 `gpt-5.6-sol`、同一篇《Attention Is All You Need》、同一个自然学生问题做干净 A/B。基线环境没有 `skills/` 目录；实验组只增加 `$crux` 和 `coach`，提示词不再包含答案披露规则。

| 条件 | 字符数 | 问题/任务 | 是否给出关键内积结果 |
| --- | ---: | ---: | --- |
| [无 Skill 基线](transformer-baseline-output.md) | 2401 | 0 | 是 |
| [修复前 Crux](transformer-before-fix-output.md) | 1753 | 0 | 是 |
| [修复后 Crux](transformer-after-fix-output.md) | 873 | 1 | 否 |

干净 A/B 证明了修复前的 Skill 更简洁，但没有改善核心的答案泄露问题。根因是 R0-R7 只描述总体披露深度，没有标记“哪一步必须由学生完成”。

## 系统修复

v0.4.0 增加 `protected_work_ids`。在 `coach` 模式下，系统现在必须：

1. 将缺失推理按依赖顺序排列：观察提取、变换或推导、解释、因果归因、扩展实验；
2. 保护学生尚未完成的最早一步；
3. 响应计划分别声明 `elicited_work_ids` 与 `revealed_work_ids`；
4. 两者与受保护项发生泄露交叉时，审计报 `OWNERSHIP_LEAK`；
5. 禁止回答当前问题后，再用一个更难的新问题制造“正在辅导”的假象。

这里仍有边界：确定性 Auditor 检查的是结构化响应计划中声明的 ID，不能仅靠字符串规则理解任意自然语言是否构成等价泄露。生产系统需要结构化生成，或在发送前用独立语义审查器把草稿映射成 `revealed_work_ids`；不能让 Actor 自己写答案、自己标注、再自己宣布通过。

## 未见任务 forward test

### Adam 偏差修正

[原始输出](adam-after-fix-output.md)展开了递推式和期望，但停在有限等比级数：

\[
C_t(\beta)=(1-\beta)\sum_{i=1}^{t}\beta^{t-i}
\]

它没有给出级数结果，也没有直接推出两个修正因子，只让学生完成这一关键步骤。通过。

### ResNet degradation

这个任务连续暴露了两个更细的问题：

- [第一次](resnet-attempt-1-output.md)：系统讲完训练误差解释和机制边界，再另造 ablation 题。失败。
- [第二次](resnet-attempt-2-output.md)：系统不再讲机制，但仍先说出 plain-34 与 plain-18 的训练误差方向。部分泄露。
- [最终版本](resnet-after-fix-output.md)：系统只指向 Fig. 4 的具体曲线，让学生先报告训练与验证误差关系，没有说出方向。通过。

这促使系统把“从图表提取观察”放在“解释观察”之前。论文精读不是只保护高阶推理；如果学生尚未读出证据，观察本身也属于学生的工作。

## 现在能下什么结论

这三项 smoke test 表明，新规则修复了已知失败，并在两类未见任务上产生了预期行为。它仍不是学习效果证明：每个最终条件只有一次生成，没有盲评者，也没有延迟迁移测试。

正式评测必须遵循[四条件协议](../../docs/evaluation-protocol.md)：无 Skill、Prompt-only、Skill-only、Skill + supervisor；每题至少三个独立生成，隐藏答案与所有权目标，盲评答案泄露、正确性、来源忠实度、单步聚焦和下一轮质量。

运行版本、论文哈希、任务 ID 和所有文件哈希见 [run-metadata.json](run-metadata.json)。
